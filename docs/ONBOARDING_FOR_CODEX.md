# 客户首次启用：由 Codex 引导并接续

这是安装后的执行规则。当前开发版尚未完成全部自动化，不能将本文件视为实现成功证据。

## 客户只处理本人操作

- 浏览器明确要求确认添加/启用扩展或授权连接时，打开准确入口并说明要确认的权限。
- 抖音、星图、B站实际出现登录要求时，引导客户在官方页面登录、扫码或完成验证码。已有有效登录时直接复用，不要求重登。B站公开查询若可用，不额外要求登录。
- Monet 按已验证模块的官方认证流程执行；不得猜接口或要求客户提供客户端私有token。
- 只有确实需要重启 Codex/托管宿主时，集中一次说明，并先写好接续文件。不能承诺后台改变当前聊天已经加载的工具清单。

客户不负责运行命令、配置端口、复制cURL/Cookie、解析接口、选择组件、填写裁切坐标或判断安装成功。

## Codex 的责任

1. 读实际安装报告和检查点，自动完成缺失工具部署、校验、备份、注册和协议自检。
2. 检查daemon、扩展、协议和实际监听地址；不能固定假设10086可用。端口冲突与版本不匹配属于技术项，由Codex诊断。涉及正在使用的共享服务时保留当前工作，不能为安装本模块擅自中断其他任务。
3. 只在页面或工具明确需要本人操作时提示客户。提示应包含平台、准确页面、一个具体操作和完成后的接续动作。不要只说“请登录”后结束整套任务。
4. 客户完成操作后重新读实际状态，再完成星图捕获/加密保存及只读self-test；客户口头说已登录不能代替检查。没有实现的捕获路径标engineering_pending，不伪装成需要客户继续登录。
5. 记录有效会话与已验证步骤，升级不清除登录。验证码或会话过期只阻塞相关模块，其余任务继续。
6. 重新检查注册持久性，调用真实取材任务，生成用户规定的两页验收PPT；程序与实际看图分别记录。完成后报告文件路径、安装状态、验证范围和剩余项。

## 状态分类

- technical_failed：下载、校验、端口、版本、注册或配置失败。由Codex修复，客户不执行技术命令。
- customer_action_required：明确需要本人登录、扫码、验证码或权限确认。列出具体动作，其他独立模块继续。
- engineering_pending：本发行包缺少实现或兼容验证。属于制作方未完成，不请求客户用反复登录代替。
- ready：有实际成功证据，仅解锁已测能力。服务可达、登录成功、取材成功和视觉验收分别记录。

## 客户提示示例

“请在已打开的星图官方页面完成登录或扫码。我会在登录完成后检查页面、建立本机加密会话，再验证一条只读查询。你不用复制Cookie、运行命令或修改配置。”

如果当前聊天不能等待用户操作后自动执行，保存检查点，在同一聊天收到用户回复后继续；不宣称进程仍在后台等待，也不擅自创建新聊天。
