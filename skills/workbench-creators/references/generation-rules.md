# 生图创作与验收规范

版本：4，2026-11-02。源于本项目研究记录和用户最新要求。适用于提案配图、真人真实场景概念示意、达人创意概念封面与角色场景图；与 Monet 接入方式无关。由工作流自动执行，不要求客户每次重述。用户本轮明确要求优先于默认规则，例外需记录原因。

## 统一默认与例外判断

**达人示意图、达人创意封面、真人COS图和非达人场景概念图，一律以真人实拍为默认，优先考虑符合内容形式的手机横/竖屏直拍效果。** 达人过往风格参考用于外观、花字、构图和内容语言，不自动覆盖这一默认。
Codex 应先根据页面内容和图位用途判断：若这里确实是游戏画面展示、游戏内场景/角色/玩法的概念展示，可使用相应游戏视觉，无需为了套真人规则把游戏内展示改成线下实拍。用户明确指定的其他风格仍优先。
判断依据写入图位计划；“游戏客户”“游戏题材”“达人COS”“采用官方CG作造型参考”均不足以判为游戏内展示。不要每次让客户手动分类；只有上下文确实无法判断、且会实质影响成图时才问。生成的游戏内概念图仍须与真实游戏截图区分，不冒称已上线画面。

## 接入方式：必须进入每次任务的生成与审核

集成到 Workbench 生图入口的 Skill：每批规划提示词前读取本规范；任务调用时带入对应图位的要求，不只在最终用户手册中提一句。已读取且未变化的规范不需要每张重读，但每个任务都须落实适用字段。换项目/换聊天时从落盘记录恢复，不靠聊天记忆。
调用接口负责生成，Codex 负责审看参考、构思与验收。缺少可用参考时明确记录，不能谎称已参考；关键身份不明确则阻塞该图位，其他图位继续。

## 1. 先认识达人，再写人物和封面

本节身份核验适用于指定达人；无指定身份的概念人物不强制找达人或索要人脸参考，按后述真人场景规则构思，不杜撰其真实身份。

- 以平台账号 ID、主页和作品 ID 核对人，不凭昵称、标签或搜索排名确认。
- 达人创意封面优先审看2–3张具有代表性、画面清楚的近期真实封面；若仅有更少可用样本，记录样本限制，不为凑数反复取材。根据需要看视频片段，不把封面观察说成表演或声音分析。
- 记录真实形象锚点：脸部外观、发型/发色、典型服装、遮面特征、道具、标志动作。浑元的头套和唢呐等是研究中的例子，不是所有人物通用描述。
- 给每张参考标明用途：本人身份、官方角色造型、封面风格、场景或构图。禁止让一张风格图无意覆盖另一个人的脸或官方服装。
- COS 图明确真人外观与角色设定如何结合；发型、服装、配饰和关键道具按本轮官方设定/明确创意执行，不只换衣服。缺少身份参考时不生成“已准确还原本人”的结论。

## 2. 花字是否添加及如何添加

- 从该达人的真实封面确定标题策略：无字、简单字幕、气泡字幕、手写花字或其他实际样式，保存样本来源和判断。
- 日常封面无字时默认不加花字；有字也不机械把所有画面填满标题。混合风格按本次内容形式选择，不把一次有字样本当成所有作品都如此。
- 有字图位记录字体形态、粗细、颜色、描边/阴影、位置、行数和主次；标题本身来自已确认选题，不复制无关参考文案。
- 尽量用可编辑 PPT 文字或确定性合成完成标题，减少生图错字；若图内生成，逐字检查，避免重复标题、压脸和裁掉文字。
- 多人同台封面选择明确的主导风格或说明融合理由，不把每人的花字风格同时堆入一张图。用户明确指定可覆盖默认，但记下原因。

## 3. 同页多图必须有不同的表达作用

- 先按整页规划组合，再分别写提示词，不能只把相同提示词换人物名或昼夜词。
- 每张图写清：信息作用、人物姿态/动作、景别、机位/角度、构图、人物在画面中的位置及与其他图的差异。
- 同页独立图位避免姿势、构图、机位全部相同；至少有实际可见且有意义的差异。只换背景颜色、衣服颜色、左右翻转或裁同一图，不算足够差异。
- 可按内容组合“远景交代装置/场地＋近景表现人物/反应”“白天互动全身＋夜间角色半身压迫感”“参与者视角＋现场全景”。不为差异而破坏内容或强制每页套同一组合。
- 若需要同机位前后对照，可保留相同机位和构图，明确这是对照图组；用动作/形态/事件变化体现对比，不为追求多样性破坏对照。
- 同图位的两张候选是备选，不等于两个独立图位；选中一张即可，不默认将近似候选同时塞入 PPT。

## 4. 风格与空间关系

- **所有表现现实活动、人物和场景的图位，包括没有指定达人的概念示意，默认真人、真实场景、实拍摄影质感。** “概念”“创意”“游戏营销”“效果图”不构成转为动漫、动画、游戏 CG 或3D渲染的理由。人物应呈现真人的皮肤、头发、衣料、表情和动作，避免卡通脸、塑料皮肤、游戏建模人物。
- **先理解创意，再选择拍法。** 从页面提取“谁在什么地方、做什么、与谁/什么互动、反差或看点是什么、这张图要证明什么”。把抽象卖点转成能被现场镜头捕捉的具体瞬间；不只凭关键词生成漂亮场景，也不擅自改掉创意机制。关键机制含糊时先检查上下文，确实无法确定才问。
- **优先考虑真实手机横屏/竖屏直拍。** 根据内容形式、页面图位和叙事目的选择16:9、9:16或其他已确认比例，不一律横屏。可选择参与者第一视角、旁观者随手拍、自拍或现场记录；具有自然光/真实现场光、可信曝光与透视、自然表情、抓拍感和适度生活细节。不要机械添加噪点、模糊或过曝来冒充真实，仍须满足清晰度和画面表达。
- 真人主体与环境应使用相容的摄影语言：合理的人物尺度、站位、接触、遮挡、光影与景深；避免真人贴在 CG 背景上。创意需要夸张道具或装置时，将其表现为现场实体装置、服装、灯光或舞台效果，先体现实际可见的创意，不擅自用魔法特效替换机制。
- 游戏IP元素可出现在现实场景中，例如官方吉祥物、人偶服、装置、屏幕或道具；保留所需官方造型，但不能因此把周围真人和整张场景一并游戏化。官方CG参考只承担设定/造型/场景依据时，在提示词中明确转译为现实环境与真人COS。
- 达人原生内容封面同时遵循其真实内容质感和样本风格；不自动升级成电影海报、油画或 CG。精致 COS 美拍可以使用真实摄影布光，不等于游戏CG。仅在用户明确要求或图位本身明确是官方3D主视觉、插画、动画等时采用相应风格，记录例外依据，不能因“看起来高级”自行切换。
- 非达人概念示意不默认添加视频标题、花字、平台 UI 或传播数据。若图位本来是拟制视频封面，才按明确内容形式和页面要求设计标题，不虚构达人样本风格。
- 写清人物在哪、做什么、镜头在哪、背景是什么；场地层级如“表演者在塔楼二层、观众在楼下”须写成明确约束。
- 同场景不同镜头共享角色外观、官方造型、装置和空间关系；改变机位不能让身份或场景结构漂移。
- 复杂滤镜、镂空、反射等说明哪些区域改变、哪些保留，以及遮挡/透视关系，先用样本验证。
- 先确定图位比例、尺寸和裁切安全区，保护脸、全身动作、关键道具和文字。透明人物图需要适合落版的轮廓与边缘；不与旁边封面重复同姿态充数。

## 5. 出图后按原图与页面图组两次检查

### 前期占位与生图尺寸必须一致规划

- 除明确的特殊用途、模板约束或用户要求外，图片比例只从 **16:9、4:3、3:4、9:16** 中选；均指宽:高。不要默认1:1，不把PPT整页比例套给所有图位。头像圆形、透明抠图和特殊拼图等按实际用途记录例外。
- 前期布图占位就确定每个 slot 的比例、PPT内 x/y/width/height 及单位、目标成图像素 width_px/height_px、缩放/裁切方式和安全区。结合页面信息层级选择横竖构图；不能只写“放一张示意图”或等生图后才决定形状。客户不必手填，由 Codex 规划。
- 提示词明确横/竖屏、比例、构图与关键主体留白；调用参数也要实际设置服务支持的比例/尺寸。只写提示词里的“16:9”不能替代接口尺寸参数。服务只支持尺寸枚举时按真实 schema 映射，不编造支持值。
- 目标像素示例：16:9 可为1920×1080，4:3 可为1600×1200，3:4 可为1200×1600，9:16 可为1080×1920。这些是规划示例，不是已确认的 Monet 支持尺寸，也不要求一律请求最高分辨率。按落版大小、清晰度、服务支持及预算确定实际规格。
- 记录“目标成图尺寸”“实际请求尺寸”“实际返回尺寸”。若服务不支持目标比例，提交前制定明确的留边/安全裁切/扩图方案；只在已有授权和预算内执行。不能静默改比例、横竖互换、拉伸人物或擅改已确认版式。无可行处理方式则仅阻塞该图位并说明缺口。
- 正常矩形图位按选定比例建框；原稿非标准图框不能擅自重排，可在框内等比放置并留边，或记录安全裁切的例外。圆角、旋转、叠放不改变底层图像比例。多格图分别规划总画布和单格尺寸，检查切开后的有效像素。
- 生图后实际读取宽高与比例；落版后再核对尺寸、裁切、安全区与主体完整性。仅修改文件扩展名或像素元数据不算尺寸合格。改图框比例或目标尺寸时同步更新构图和任务版本，不复用已失效的审核结论。

单图核对：身份锚点、角色服饰、主体/动作/场景、空间关系、质感、文字、清晰度。实际看图后才记录通过，文件存在或哈希不能代替审看。
对真人真实场景图（含非达人概念图）另核对：创意的核心动作/互动/反差是否一眼可理解；人物是否真人而非动画或游戏模型；环境、皮肤、衣料和光影是否实拍可信；横竖比例和镜头是否符合预定内容形式。精美但创意表达错误、或默认生成成CG，均不能通过，需定向修改。
同页图组核对：各图分工是否清楚，姿态/景别/机位/构图是否有计划中的差异，角色是否一致，是否重复表达，裁切与花字是否相互冲突。原图过关不等于放进页面后过关。
失败记录具体原因，定向修订；预算和授权范围内处理失败项，不把全部已通过图片重生。不能宣称规则保证生成模型每次都准确；靠提交前检查和出图后验收发现偏差。
概念图不能冒充真实合作、过往作品或活动实拍，直播 UI 不制造未经标明的虚假传播数据。

## 6. 图位计划需要承载的字段

在现有图位清单或其 JSON 补充记录中保存，沿用原有 slot_id/slide_id，不要求更换整个表结构：

| 字段 | 内容 |
|---|---|
| generation_rules_version | 本规范版本，用于接续与变更复查 |
| aspect_ratio / ratio_exception_reason | 16:9、4:3、3:4、9:16，或特殊用途与依据 |
| placement_box / placement_unit | PPT占位 x/y/width/height 及单位；以原稿实际尺寸为准 |
| target_width_px / target_height_px | 目标最终成图像素，和比例一致 |
| requested_width_px / requested_height_px / provider_size | 实际请求像素或服务尺寸枚举；按实际接口记录 |
| actual_width_px / actual_height_px | 文件落盘后读取的实际像素 |
| fit_mode / safe_area / size_fallback | 等比适配/裁切策略、关键主体安全区、不支持目标规格时的明确方案 |
| creative_intent / visible_moment | 创意要表达的机制与镜头可见的具体瞬间 |
| identity_mode / realism / capture_format | 指定达人或普通概念人物；真人实拍默认；横/竖屏直拍或明确风格例外及依据 |
| creator_identity / appearance_anchors | 核实身份与具体形象特征 |
| reference_reviews | 参考路径/哈希、来源、用途、实际观察、局限 |
| cover_style / title_policy | 封面风格；none/subtitle/decorative及依据 |
| title_style / title_text / title_render_mode | 花字样式、标题、PPT叠加/合成/图内生成 |
| image_role / pose_action / shot / camera / composition | 图位目的、动作、景别、机位与构图 |
| same_page_group / differentiation | 同页组及相对其他图的实际差异；对照例外说明 |
| continuity / locked_elements | 同场景一致项和不可改元素 |
| preflight_review / image_review / group_review | 提交前、单图和同页图组的检查状态、问题及修订 |

字段在任务规划时落实；非适用项明确 n/a，不让客户逐项填表。程序可检查缺字段、引用缺失及选项支持；身份、风格和图组差异需视觉判断，不能用“字段都非空”冒充审美验收。

## 集成验收用例

集成方验证：无字达人样本不默认加花字；气泡字幕与手写花字按各自样本区分；标志性人物形象进入提示词和审核；同页两独立图位具有有效镜头/姿态差异；明确同机位对照不会被误拦截；参考缺失不伪称已审看。可先用离线任务计划验证路由，真实生成与落版待 Monet 接通并取得相应授权后验收。
新增必验：没有达人名字的线下互动概念图默认真人实拍、不索要无关人脸参考；游戏营销场景不会自动生成成游戏CG；官方CG造型参考可转译为真人COS而不继承渲染风；手机竖屏任务保留竖屏；明确要求插画的图位允许覆盖默认；模型输出虽漂亮但遗漏核心创意互动时不通过。
尺寸必验：四种常用比例均可进入图位规划；占位与目标像素匹配；缺尺寸的任务不能直接提交；服务不支持规格时不会静默换比例；目标/请求/返回尺寸分开记录；既有非标准图框与头像等合理例外不被误拦截；出图及最终裁切不会丢失关键人物、动作或标题。
