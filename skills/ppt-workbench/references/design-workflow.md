# 设计与改稿：按项目调整

这些是可组合的制作方式，不是固定阶段或审批流程。用户可先套模板、先解决关键视觉、退回调整内容，也可只要求文字稿。

本规则同时适用于 HTML deck 与原生 PPTX。新建、整页重排、风格调整时读取并应用；只改指定文字/颜色时保留当前设计，不借此扩大范围。下列数值是常见宽屏提案的起点，不是程序门禁；用户要求、强制模板和已确认设计优先。不同画幅、中文密度、现场讲述或屏幕阅读用途应调整。

## 内容与版式

将 BRF 的必须表达项、思维导图中的创意逻辑和原始资料对应到具体页面。把需求转成受众能理解的叙述，不逐条机械搬运。区分原始事实、创意建议与待确认机制；缺失信息按用户要求记录，不编造数字或达人经历。

用户要黑底白字时，集中处理标题、信息层级、并列/递进/因果关系和图文空间。暂不做无关装饰。占位图的内部记录包含要解释的内容、素材类型、比例、主体位置和来源约束；页面只保留用户需要的简洁占位标识。

对强制模板，先提取尺寸、标题/页脚位置、字体、Logo 与安全区。文字稿可简化配色，但保留后续必须遵守的几何约束。如果保留原生母版和对象是硬要求，选原 PPTX 编辑路线。

默认每页突出一个主要信息，保持标题位置与字阶一致。卡片、表格、步骤、大数字、整图和留白均按内容关系选择，不把所有页面强制改成三卡片。无其他要求时可建立 1 深色、1 浅色、1–2 强调色与 4–5 档字号；参考稿或用户要求优先。

deck 画布 1920×1080，常用边距 128px 后可用高度 824px。估算行高×字号×行数，再用 check 实测；原生 PPTX 保留实际画幅。内容多时优先调整布局、在允许改写时精简重复表达，或按授权拆页，不无止境缩字，也不为变简洁删除关键机制。

## 每页先决定视觉主次

在首次排版或结构重排前，确定本页的阅读路径，简要写入项目 notes/style.md；已有相关记录时只更新变化页。无需逐页向用户追问或额外审批，也不把这些制作说明写进 PPT。

一页一条即可：`页ID｜核心意思｜第一眼看什么｜内容关系/主辅区域｜字号与强调色｜必须保留什么`。

例如：`联动创意页｜三位达人共同完成挑战｜联合封面与创意标题｜右侧主图约六成、左侧机制和身份｜标题36pt、正文18pt、金色强调挑战规则｜原文案、人物身份与作品来源`。这是示例，不能把它的数字或角色套进所有项目。

- 第一视觉重点可以是创意标题、主图、机制图或关键数字。先决定谁主导，再分配面积、字号、颜色；避免所有模块同样醒目。
- 按理解顺序组织：主结论/主视觉 → 支持机制或证据 → 身份、来源和补充。标题不必每页都是最大对象，但不能被无意义装饰抢走注意力。
- 黑底白字稿也要建立主次：用大标题、粗细、对齐和空间安排阅读顺序。图片未就绪时按预期作用保留空间，不为“视觉丰富”临时加无关图。

## 字号：明确层级，按阅读用途选择

下面统一用 PowerPoint 的 **pt**。本工作台 deck 方言中 `1px=0.5pt`，写 HTML 时把表中 pt 乘2，例如36pt标题写72px；不要将原生 PPTX 的 pt 值直接当 deck px。其他编辑工具按自身单位换算。

| 角色 | 常见起点 | 使用判断 |
|---|---|---|
| 页面标题 | 32–44pt；常用36pt | 一眼找到本页主题；模板固定标题位置/字号优先 |
| 分区标题 | 20–26pt | 高于正文，低于主标题，靠间距建立分组 |
| 现场展示的正文 | 18–24pt | 控制行数；避免演示页变成供逐字阅读的文档 |
| 供屏幕细读的提案/文字初稿 | 14–18pt | 用户指定14pt时遵守，不自动放大到挤坏原稿 |
| 主数字或短主张 | 48–72pt，可按内容调整 | 确实是本页重点时使用；长标题不硬塞进此档 |
| 来源、页脚、补充标签 | 10–12pt起 | 仅用于辅助信息，不把关键机制压成脚注 |

每套稿实际选4–5档即可，不必全部使用。通常让主标题约为正文的1.5–2倍，再结合粗细、颜色、空间拉开层级；模板和整体观看效果优先，不机械计算比例。强调正文中的关键短语时优先用字重/颜色，避免同一段不断变字号。可选一套中文字体用不同字重；没有品牌理由时不堆多种字体。

## 色块：建立信息区域与重点

建立统一背景色/主色、辅助色和少量强调色。主色形成整稿识别，辅助色分区，强调色只标记最重要的动作、结论或关键词。60–70%的主导视觉权重可以作为构图参考，不是要测算像素面积，也不要求大多数页面铺满鲜艳颜色。

- 同一创意、机制或证据组可放在一个完整色面中，减少把每句话拆成小卡片。大色块应与信息关系一致。
- 页面已有强主图时，色块可以退为安静的承托区域；黑白文字稿用黑白反差和空间即可，不自动加彩色装饰。
- 不把每张卡片、每段文字都设为强调色。深色底上的正文保持清楚对比，避免中灰小字或花图上直接压字。
- 图片上叠字时选平静区域，必要时加底色/遮罩承托。Logo和真实截图保持应有的完整内容；不能为铺满色块裁掉证据。

## 版式：按信息关系选择，给主角足够空间

| 当页表达 | 可以采用的结构 | 重点 |
|---|---|---|
| 创意＋解释 / 观点＋证据 | 左右主辅；约60/40或65/35作为起点 | 分给主角更大的区域，不默认五五开；左右方向按阅读关系决定 |
| 多位达人 / 多个方案比较 | 对齐的2–3列或矩阵 | 每列是完整的信息单元；若确实平等比较，等面积合理 |
| 流程 / 参与机制 | 有方向的步骤、泳道或关系图 | 顺序和关系要能直接看懂；不把步骤当互不相干的卡片 |
| 一个强创意 / 作品展示 | 半页或更大的主图＋短说明 | 图大到能看懂主体；身份头像等辅助图不抢同等面积 |
| 一个关键数字 / 判断 | 大数字或短结论＋少量证据 | 不为做大数字页编造数据，不把多个重点都放大 |
| 真实作品与提案示意 | 清楚分区、分别标注用途 | 帮助读者区分事实依据与尚未执行的想法 |

先定网格、页边距和主辅区域，再摆对象。相同角色保持一致间距和对齐线；不同角色允许不同面积。常见13.33×7.5英寸宽屏可从约1.3–1.5cm边距、0.6–1cm模块间距起步，再按模板和实际密度调整；deck 默认128px边距是另一套起点，不将两者叠加。

留白用于分组和引导视线。约两成留白可作视觉参考，不是机器验收比例；允许刻意偏左、上重下轻或非对称。避免一边挤满、另一边空着却没有构图目的。内容稀少时可以放大真正的重点、调整位置，不凭空补文案；内容密集时优先处理信息层级，不一律平均切成三卡片。

## 整稿节奏与视觉一致性

- 选择与模板/参考一致的少量重复特征，例如标题位置、图片框形式、编号或品牌色带，并在对应页面延续。已有模板无需再叠一套装饰主题。
- 在整体查看时检查连续页面：内容关系不同，却连续使用同样的三卡片/同样左右栏时，重新选择版式。真实比较页、系列达人页需要重复结构时保持一致，不为了变化打乱可比性。
- 主视觉页、解释页、证据页、章节页可形成疏密与大小变化；不强制固定交替顺序。
- 不默认给每个标题加装饰横线、每个卡片加彩色左边条、每页塞图标。用户模板已有这些形式时照模板；装饰是否保留由用途与参考决定，不按所谓“AI风格”一律删除。

## 视觉检查：不仅看有没有溢出

首次布局、美术/配图变化及交付视觉检查时，结合 [预览与复查](review-and-annotations.md) 进行。先看相关联系表判断节奏，再看有风险的清晰单页；不为以下清单重复读取未变全稿。

1. **重点**：缩略图状态下是否能识别第一视觉重点？是否有多个同等抢眼的标题/色块？缩略图不能证明小字可读。
2. **阅读路径**：标题、机制、图和证据的顺序是否帮助理解？是否把需要一起看的内容拆散？
3. **比例**：主图/主张是否有足够空间，头像/页脚/装饰是否过大？人物和截图的裁切是否符合用途？
4. **字阶与对比**：重要内容是否明显高于辅助说明？深色底、花图上的文字是否清楚？实际尺寸下是否容易阅读？
5. **留白与对齐**：空处是否有构图作用，密处是否过挤，重复单元是否沿同一网格？
6. **整组节奏与忠实性**：是否过度重复一种布局，是否符合模板；是否为追求简洁误删机制、改了事实或丢了用户手改？

只报告实际观察到的问题；程序 check/原生差异检查不自动判断这些审美问题。满足本轮要求即停止，不能借视觉检查反复重做用户已经认可的设计。未做视觉检查时明确写未验证，不宣称这些项已通过。

## 多轮校准

将本轮反馈对应到页码和稳定元素。未涉及页保持当前内容；用户要求全局一致性调整时才扩大范围。confirmed 可分别记录已确认文案、事实、逻辑或版式，不将“确认内容”误解成禁止后续视觉调整。

每轮修改后记录本轮目的、变化页、未解决事项。当前文件优先于聊天记忆。用户提出新要求可替代此前决定，要更新记录而非让旧决定阻断工作。

## 素材与美术

补图先明确图片要证明或解释什么，再找用户素材、达人真实过往内容或其他授权来源。确认作品与达人对应关系；缺少真实资料时不以生成图冒充其经历。记录来源、版本、适用项目与裁切意图。

官方资产要核对产品/IP、活动和版本。图片固定显示区域后使用 cover/contain，不拉伸；品牌 Logo 按使用要求保持完整比例。已有素材摘要可以辅助筛选，真正判断构图与细节时仍需看原图。

美术升级默认保留已确认的语义和事实，调整字阶、色彩、背景、图文比例与层次。版式变化影响表达或需要改文案时明确记录原因，按本轮授权处理；不要悄悄删掉关键机制或让装饰遮挡内容。

## 参考记录

用 deck_context.references 区分 content/layout/visual/template；详细配色、字号、网格、密度、图文关系存 notes/style.md。记录由实际观察产生，不能先编测量结论。参考图有变或摘要不够用时重新查阅；不要生搬“每轮只看几张”或宿主专属的图片保留上限。
